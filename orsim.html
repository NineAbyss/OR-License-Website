Meet ORSim

ORSim plays the client.

Real projects start with requirements that are not fully spelled out. ORSim lets agents ask for the missing business facts at any point, but it never does the optimization work for them.

Example

From a one-line brief to a workable timetable.

Follow an agent as it plans a small production schedule. It asks questions, builds the model, writes code and checks its work, while ORSim fills in business facts along the way.

Example · The client’s brief

Three batches. One morning shift.

“Prepare a timetable for today’s food-production batches using our mixer and packer. Clarify the operating requirements before delivering the plan.”

A made-up, simplified scenarioLoosely based on Task 02: one-day food production in batches.

Everything below, including the dialogue, numbers and DEMO IDs, was invented for illustration. It is not taken from the benchmark’s rules, a real run, or measured results.

Correct a convenient assumption

A
Agent
So I can run product B immediately after product A on the mixer, just as I can run A2 immediately after A1?
OR
ORSim
No. Switching products in either direction requires 15 minutes of cleaning on the mixer. Cleaning occupies the mixer and must finish before the next product starts mixing. There is no extra turnaround between batches of the same product, and the packer needs no product-change cleaning.

Asking a leading question does not make a wrong assumption true.

The full workflow

The client supplies facts. The agent does the work.

The agent can go back to the client while modeling, coding or checking.

THE CLIENT’S MATERIAL

Start from the business, not a ready-made model.

The agent reads the requirements, the data and what it has to deliver. It has to work out what to model before deciding how to solve it.

The material is kept as the client provided it; only identifying details are removed.

ASKING THE CLIENT

Ask for the facts that are missing.

ORSim answers from what the client knows. The agent can ask at any point in its work, not only at the start.

ORSim shares business facts only. It gives no modeling advice and never builds the solution.

BUILDING THE SOLUTION

Turn what it learned into a working solution.

Working in a coding agent such as Claude Code, the agent builds the model, writes the solver code and produces the required output files.

A convincing explanation is not enough; the agent has to hand in real output.

GRADING

Check, improve, then submit.

The agent can check its own work and keep asking questions. After it submits, hidden checks test the plan against every rule and compare it with the expert solution.

A plan that breaks any rule scores zero, however good its numbers look.

This explains the workflow. It is not a live simulator or a recording of a real run.
